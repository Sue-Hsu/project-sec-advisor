# 免費工具研究與選型

先由風險和可驗證目標推導檢測方法，再找工具。依專案情境從 SAST、SCA、Secrets、組態、DAST、Fuzzing、Binary、Mobile、Desktop 等方法選取候選。Semgrep、Gitleaks、Trivy、OSV-Scanner、ZAP、Nmap 可作為候選發現入口；推薦名單由實際覆蓋決定。

## 每款入選候選的查核欄位

- 來源與現況：名稱、官方網站與儲存庫、開發／維護者、官方發布來源、版本、維護狀態、查核日期及來源連結。核對同名套件的發布者；結合發布紀錄、安全回應與相容性判斷維護狀態。
- 免費條件：開源或免費版的授權、使用限制與必要帳號；不明確的條件標示「未查證」。
- 專案適配：支援語言、平台、檢測類型、實際使用情境、可具體驗證的項目與盲點，以及執行平台、依賴、CLI／自動化能力。
- 操作與隱私：是否需要外部服務或 API Key、是否傳出原始碼或敏感資料、安裝與執行副作用。需要登入、雲端處理或上傳時明列前提與資料去向，保留為待授權步驟。

官方文件與安全公告是能力、授權及發布來源的主要證據；第三方文章或清單用於發現候選，再回官方來源核對。對同功能候選比較檢測深度、語言支援、誤報成本、隱私與增量覆蓋，選出具有新增檢測價值者。對入選且計畫執行的工具按需查本機現況，區分「已確認可用」、「未找到」與「未查證」。將版本命令、`npx`、`pipx run` 及容器拉取列為可能執行外部程式碼的步驟，依主文件的授權界線處理。

## 分級與覆蓋

- 必要：對高優先風險具明確增量證據，成本及副作用可接受。
- 建議：補主要工具的特定盲點。
- 選用：僅在特定環境或風險成立時使用。
- 不適用：架構不符，保留簡短理由即可。

每個安全要求映射「工具可直接驗證／只提供線索／需人工測試／目前無法驗證」。本次若未找到已查證的適用免費工具，記錄已查來源、研究限制及具體人工審查方法。工具零發現時只記錄該版本、設定與範圍的觀察結果，驗證狀態仍依實測證據判定。將執行命令及權限、環境、資料、停止條件寫進待授權的測試計畫。
